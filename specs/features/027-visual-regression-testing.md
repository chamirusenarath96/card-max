# Feature: Visual UI Regression Testing (027)

## Status
- [x] Spec drafted
- [ ] Spec reviewed
- [ ] Implementation started
- [ ] Tests written
- [ ] Done

## Purpose
Extend the Playwright E2E suite with automated visual verification so that broken
layouts, missing components, and rendering regressions introduced by automated agents
or manual changes are caught in CI before reaching production.

## User Story
As the maintainer, I want Playwright to take screenshots of critical views and compare
them to known-good baselines so that any layout regression is caught automatically
before a pull request is merged.

## Scope

### In Scope
- Playwright screenshot assertions (`expect(page).toHaveScreenshot()`) for four critical views:
  1. Offer grid (default state, first page)
  2. Filter drawer (open state)
  3. Hero search bar (initial state)
  4. Empty / error state (no results)
- Structural sanity checks using `data-testid` selectors that confirm key elements are
  visible on every page load without relying on specific offer data
- Snapshot baseline images stored in `e2e/snapshots/` and committed to the repository
- Pixel-diff threshold: ≤ 0.2% of pixels may differ (tolerates sub-pixel antialiasing)
- Runs inside the existing `e2e` CI job against the production build (`npm run build`)
- Update mechanism documented: run `npx playwright test --update-snapshots` locally to
  regenerate baselines after intentional UI changes

### Out of Scope
- Cross-browser visual regression (Chromium only — matches the existing E2E suite)
- Mobile viewport screenshots (desktop viewport only in first iteration)
- Third-party visual regression services (Percy, Chromatic, Applitools)
- Full-page comparison for pages with dynamic content — use clipping or mock data

## Data Contract
No database or schema changes.

## API Contract
No new API endpoints. The visual tests mock the `/api/offers` response to avoid
dependency on live data, ensuring baseline images are stable across runs.

## Technical Approach

Follow the E2E test pattern from `/new-page` steps 6–7 for the Playwright test structure.
Follow `/new-github-action` step 4 for the artefact upload pattern.

### File locations (from `/new-page` step 7 convention)
```
e2e/
  visual.spec.ts          ← new visual regression test file
  snapshots/              ← committed baseline PNG files (auto-generated by Playwright)
    visual.spec.ts-snapshots/
      offer-grid-chromium-linux.png
      filter-drawer-open-chromium-linux.png
      hero-search-chromium-linux.png
      empty-state-chromium-linux.png
```

### Mock response (from `/new-page` step 7 API mocking pattern)
```typescript
const MOCK_OFFERS = [/* ... minimal fixture matching OfferSchema */];

test.beforeEach(async ({ page }) => {
  await page.route("**/api/offers**", route =>
    route.fulfill({
      status: 200,
      contentType: "application/json",
      body: JSON.stringify({
        data: MOCK_OFFERS,
        pagination: { page: 1, total: 1, totalPages: 1, limit: 20 }
      })
    })
  );
});
```

### Screenshot assertions (`e2e/visual.spec.ts`)
```typescript
import { test, expect } from "@playwright/test";

test.describe("Visual regression", () => {
  test("offer grid matches baseline", async ({ page }) => {
    await page.goto("/");
    await page.waitForSelector('[data-testid="offer-grid"]');
    await expect(page.getByTestId("offer-grid")).toHaveScreenshot(
      "offer-grid.png",
      { maxDiffPixelRatio: 0.002 }
    );
  });

  test("filter drawer open state matches baseline", async ({ page }) => {
    await page.goto("/");
    await page.getByTestId("filter-toggle").click();
    await page.waitForSelector('[data-testid="filter-drawer"]');
    await expect(page.getByTestId("filter-drawer")).toHaveScreenshot(
      "filter-drawer-open.png",
      { maxDiffPixelRatio: 0.002 }
    );
  });

  test("hero search bar matches baseline", async ({ page }) => {
    await page.goto("/");
    await expect(page.getByTestId("hero-search")).toHaveScreenshot(
      "hero-search.png",
      { maxDiffPixelRatio: 0.002 }
    );
  });

  test("empty state matches baseline", async ({ page }) => {
    await page.route("**/api/offers**", route =>
      route.fulfill({
        status: 200, contentType: "application/json",
        body: JSON.stringify({ data: [], pagination: { page: 1, total: 0, totalPages: 0, limit: 20 } })
      })
    );
    await page.goto("/");
    await expect(page.getByTestId("empty-state")).toHaveScreenshot(
      "empty-state.png",
      { maxDiffPixelRatio: 0.002 }
    );
  });
});
```

### Structural sanity checks (same file)
```typescript
test.describe("Structural sanity", () => {
  test("critical data-testid elements are visible", async ({ page }) => {
    await page.goto("/");
    await expect(page.getByTestId("offer-grid")).toBeVisible();
    await expect(page.getByTestId("filter-toggle")).toBeVisible();
    await expect(page.getByTestId("hero-search")).toBeVisible();
    await expect(page.getByTestId("pagination-controls")).toBeVisible();
  });
});
```

### CI artefact upload on failure (from `/new-github-action` step 4)
In the `e2e` job of `ci.yml`, add after the Playwright run step:
```yaml
- name: Upload visual diff artefacts on failure
  if: failure()
  uses: actions/upload-artifact@v4
  with:
    name: visual-diffs-${{ github.sha }}
    path: e2e/snapshots/
    retention-days: 7
```

### Playwright config update
Add `snapshotDir` in `playwright.config.ts`:
```typescript
snapshotDir: "e2e/snapshots",
```

### Updating baselines
When an intentional UI change causes snapshot failures, regenerate locally:
```bash
npx playwright test e2e/visual.spec.ts --update-snapshots
git add e2e/snapshots/
git commit -m "test: update visual regression baselines"
```

## Edge Cases
- Font rendering differences between CI (Linux) and local (macOS/Windows) cause false positives — baselines must be generated on Linux (CI) using `npx playwright test --update-snapshots` inside a Docker container or on a GitHub Actions runner
- Animated elements (typewriter placeholder, hover states) — use `page.evaluate(() => document.getAnimations().forEach(a => a.cancel()))` before taking the screenshot, or clip to a static region
- Dynamic data in offer cards (merchant names, discount labels from mock) — mock data must be deterministic; use a fixed `MOCK_OFFERS` array in the spec
- Snapshot file naming: Playwright appends `-chromium-linux.png` on Linux CI — the committed files must match this suffix exactly
- `filter-toggle` or other testid renamed during refactor — structural sanity tests will catch this immediately and surface the missing `data-testid` as a CI failure

## Notes
- Implementation: use the `/new-page` command for the E2E test pattern (steps 6–7); use `/new-github-action` for the artefact upload step (step 4)
- Playwright snapshot testing docs: https://playwright.dev/docs/screenshots#taking-screenshots
- Generate initial baselines by running `npx playwright test e2e/visual.spec.ts --update-snapshots` on a Linux machine or inside a Docker container to match CI's rendering environment
- The `maxDiffPixelRatio: 0.002` (0.2%) threshold is intentionally strict — increase to `0.01` (1%) if antialiasing differences on CI runners cause flakiness
- Spec 016 (security CI) and spec 025 (CI dashboard) are independent of this spec — implement in any order
