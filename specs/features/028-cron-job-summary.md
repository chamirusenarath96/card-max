# Feature: Cron Job Summary in CI Dashboard (028)

## Status
- [x] Spec drafted
- [ ] Spec reviewed
- [x] Implementation started
- [ ] Tests written
- [ ] Done

## Purpose
Extend the CI test results dashboard (spec 025) with a dedicated panel showing the
most recent runs of all scheduled workflows so that the maintainer can see at a glance
whether the daily crawler, spec-writer, implementer, and Atlas warmup jobs are healthy
— without opening the GitHub Actions UI.

## User Story
As the maintainer, I want the CI dashboard to include a cron job health table showing
the last 5 runs of each scheduled workflow so that I can spot a failing crawler or
broken scheduled agent at a glance without navigating into GitHub Actions.

## Scope

### In Scope
- A new `cron-summary.html` panel inside the `dashboard/` output of the `dashboard.yml`
  workflow from spec 025
- Displays the 5 most recent runs for each of these scheduled workflows:
  - `crawler.yml` (daily scrape)
  - `card-max-spec-writer` scheduled task (every 12 hours)
  - `card-max-implementer` scheduled task (every hour)
  - `atlas-warmup.yml` (every 4 minutes — summarised, not individual runs)
  - `dashboard.yml` itself (every push to master)
- For each run: workflow name, trigger time (UTC), pass/fail status, and a link to the full log
- Data sourced from GitHub Actions REST API: `GET /repos/{owner}/{repo}/actions/workflows/{id}/runs?per_page=5`
- Rendered as a static HTML table generated by a Node.js build script
- Linked from `dashboard/index.html` (added alongside Allure and LHCI links)

### Out of Scope
- Real-time streaming status (the panel is regenerated on each dashboard build)
- Alerting or notifications from the dashboard itself (GitHub Actions already creates Issues on failure)
- Cron run logs embedded in the panel (only a link to the full log)
- Runs from non-scheduled triggers (push, pull_request)

## Data Contract
No database changes. Run data is fetched from the GitHub REST API during the
dashboard build job and embedded as static HTML.

## API Contract
No new application API endpoints.

### GitHub REST API used
```
GET https://api.github.com/repos/chamirusenarath96/card-max/actions/workflows/{workflow_id}/runs
  ?per_page=5
  &event=schedule

Headers:
  Authorization: Bearer ${{ secrets.GITHUB_TOKEN }}
  Accept: application/vnd.github+json
```

Response fields used: `workflow_runs[].id`, `created_at`, `conclusion`, `html_url`.

## Technical Approach

This spec extends the workflow from spec 025 (`/new-github-action` steps 1–7 already
followed there). Only the additions to that workflow and build script are described here.

### Additional build step in `.github/workflows/dashboard.yml`

Add after the Allure generation steps and before the `build-dashboard-index.js` step:

```yaml
- name: Fetch cron job run summaries
  run: node scripts/fetch-cron-summary.js
  env:
    GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
    GITHUB_REPOSITORY: ${{ github.repository }}
```

### Cron summary fetch script (`scripts/fetch-cron-summary.js`)

Plain Node.js script (no TypeScript) that calls the GitHub REST API and writes
`dashboard/cron-summary.html`:

```javascript
const https = require("https");
const fs = require("fs");

const WORKFLOWS = [
  { id: "crawler.yml",       label: "Daily Crawler" },
  { id: "atlas-warmup.yml",  label: "Atlas Warmup" },
  { id: "dashboard.yml",     label: "CI Dashboard" },
  // Scheduled tasks that appear as workflow runs in Actions:
  { id: "card-max-spec-writer", label: "Spec Writer (scheduled task)" },
  { id: "card-max-implementer", label: "Implementer (scheduled task)" },
];

const [owner, repo] = process.env.GITHUB_REPOSITORY.split("/");
const token = process.env.GITHUB_TOKEN;

async function fetchRuns(workflowId) { /* ... */ }

async function main() {
  const rows = await Promise.all(WORKFLOWS.map(fetchRuns));
  const html = buildHtmlTable(rows);
  fs.mkdirSync("dashboard", { recursive: true });
  fs.writeFileSync("dashboard/cron-summary.html", html, "utf8");
  console.log("[cron-summary] wrote dashboard/cron-summary.html");
}

main().catch(err => { console.error(err); process.exit(1); });
```

### `buildHtmlTable` output format

A self-contained HTML fragment:
```html
<table>
  <thead>
    <tr>
      <th>Workflow</th>
      <th>Run #</th>
      <th>Triggered (UTC)</th>
      <th>Status</th>
      <th>Log</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Daily Crawler</td>
      <td>12345</td>
      <td>2026-05-12 02:00</td>
      <td class="success">✅ success</td>
      <td><a href="https://github.com/...">View log</a></td>
    </tr>
    <!-- ... up to 5 rows per workflow -->
  </tbody>
</table>
```

### Update to `scripts/build-dashboard-index.js` (from spec 025)

Add a link to `cron-summary.html` in the generated `index.html` navigation section:
```javascript
<a href="./cron-summary.html">Cron Job Health</a>
```

### Permissions (from `/new-github-action` step 3)
`GITHUB_TOKEN` with `actions: read` permission is sufficient to call the workflow runs
API for the same repository. Add to the `build-dashboard` job:
```yaml
permissions:
  contents: write    # for gh-pages push (already in spec 025)
  actions: read      # new — required for workflow runs API
```

## Edge Cases
- Workflow not found (workflow ID renamed or deleted) — skip that row and log a warning; do not fail the script
- GitHub API rate limit (5000 req/hr for authenticated requests) — fetching 5 workflows × 5 runs = 5 API calls; well within limit
- Workflow has never run (brand new scheduled task) — render a "No runs yet" placeholder row
- `atlas-warmup.yml` runs every 4 minutes — the 5 most recent runs will all be within the last 20 minutes; this is expected and informative
- Scheduled tasks (`card-max-spec-writer`, `card-max-implementer`) may not appear as standard GitHub Actions workflow files if they are Claude Code scheduled tasks — if the workflow ID lookup returns 404, render a "Not a GitHub Actions workflow" note and link to the task definition file instead

## Notes
- Implementation: use the `/new-github-action` command for the build step addition (steps 2–4); spec 025 must be implemented first (this spec extends `dashboard.yml` and `build-dashboard-index.js`)
- GitHub REST API docs: https://docs.github.com/en/rest/actions/workflow-runs
- The `GITHUB_TOKEN` is automatically available in all GitHub Actions jobs — no additional secret setup required
- For the Atlas warmup workflow, summarise runs grouped by day (rather than showing 5 runs spanning ~20 minutes) for readability — a daily success count is more useful than 5 consecutive 4-minute pings
- If the Claude Code scheduled tasks (`card-max-spec-writer`, `card-max-implementer`) do not run as GitHub Actions workflows, source their run history from the Claude Code scheduled task API or skip the panel for those two rows
